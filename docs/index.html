Philosophy

Four rules carried over from the original Pragmatic-CSS snippets, now enforced by architecture instead of discipline.

🎯 Universal by default

Classless base styles bare HTML — drop the stylesheet on any WebUI and buttons, tables, forms, dialogs and code blocks are immediately consistent. No markup rewrite required.

🧱 Pragmatic interactivity

HTML-first: <details> dropdowns, <dialog> modals, the popover API, CSS-only tabs and tooltips. The JS layer is an enhancement, never a dependency — so UI keeps working in restricted renderers.

🌗 One variable to retheme

Every color is OKLCH derived from --pui-hue. Soft variants, hover states and focus rings are computed at runtime via color-mix() — change one number, the whole system retints coherently.

🤖 AI-generation-friendly

This repo began life as prompts teaching AIs to render UI. SKILL.md continues that: a spec any code-generating agent can follow to emit correct, accessible Pragmatic UI markup.

Install

No build step, no CDN, no dependencies. Pick one of three lanes.

1 · Drop-in (most universal)
<!-- classless base + components in one file -->
<link rel="stylesheet" href="pui.min.css">
<!-- optional behavior layer (theme, tabs, toasts, ⌘K) -->
<script type="module" src="pui.min.js"></script>
2 · npm
npm i pragmatic-ui
// vite / esbuild / any bundler
import "pragmatic-ui/pui.css";
import "pragmatic-ui/pui.js";  // optional
3 · Tailwind v4
/* main.css — import order matters */
@import "tailwindcss";
@import "pragmatic-ui/tailwind/pui-theme.css";  /* tokens → utilities */
@import "pragmatic-ui/src/pui.css";              /* classless base + components */

Now bg-surface, text-muted, border-line, text-accent resolve against live pui tokens — theme switching and hue re-accenting keep working. Tailwind utilities always win over pui component classes (cascade layers), so the two systems compose instead of fighting.

For AI agents — SKILL.md

This repo's origin story: teaching assistants to render pragmatic UI. The rewritten SKILL.md is a modern agent skill — feed it to any code-generating assistant and it will produce correct, accessible Pragmatic UI markup: the component vocabulary, token rules, a11y requirements, and a degraded "restricted renderer" mode for chat surfaces that allow only inline styles.

🧭 Decision framework

Header → metrics → status → timeline → progressive disclosure → footer. The original flow, now for whole WebUIs.

🚫 Hard constraints

No JS in chat renderers, no external assets, restraint on glow — the pragmatic rules survive as explicit don'ts.

📦 Copy-paste recipes

Ready-made snippets for every component, matching the classes in pui.css 1:1.
